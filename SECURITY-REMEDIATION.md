# Main-branch security remediation

The former Supabase `setup-demo` Edge Function used the service-role key to create, delete and reset a shared demo account. The endpoint was configured with JWT verification disabled.

## Source changes

- `supabase/config.toml` now requires JWT verification for `setup-demo`.
- The handler is retired and returns HTTP 410. It no longer reads the service-role key or performs account administration.

## Deployment and credential actions still required

These commits do not modify an already deployed Supabase project. Disable the deployed function immediately or redeploy this source and configuration, then verify unauthenticated requests are rejected before invocation and authenticated requests receive HTTP 410.

Rotate/delete the former shared demo account credentials, invalidate its sessions, and rotate any provider secret that may have been exposed. Source changes do not rotate credentials. The deployment-state metadata must be regenerated by the actual deployment process; do not infer live state from Git alone.

This is a source-level mitigation, not proof of deployed remediation or a security certification.
